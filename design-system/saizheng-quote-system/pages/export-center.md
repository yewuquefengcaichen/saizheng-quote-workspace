# Export Center Override

Use this file before rebuilding the export configuration flow.

## Mission

The export center should make people feel confident about what will be produced before they click export.

## Core Experience

The export experience is no longer a generic modal with many controls. It becomes a focused configuration workspace.

## Target Layout

Use a two-column or three-zone structure on desktop:

### Left: Template Browser

- grouped template cards
- system templates and mall templates clearly separated
- selected state must feel premium and obvious

### Center: Live Preview And Capability Panel

- what fields are included
- what scenario it fits
- what downstream document path it unlocks
- readiness or validation notes

### Right: Export Settings

- customer name
- price mode
- format-specific warnings
- final export action

## Key Rules

- template selection should feel like choosing a document strategy, not filling a form
- price mode should be contextual and easy to understand
- compatibility warnings must be clear, calm, and actionable
- export should feel like the last step of a prepared workflow, not a risky blind click

## Visual Rules

- make the selected template state much stronger than it is today
- avoid excessive explanatory copy
- keep cards elegant and structured
- treat readiness, support, and validation as first-class UI objects

## Copy Tone

Use product language, not engineering language.

Prefer:

- standard quote
- mall delivery sheet
- ready to export
- requires product image

Avoid:

- internal jargon that users must decode
- long dense paragraphs

## Required States

- no match results yet
- selected template but missing required data
- selected template ready
- selected template partially supported

## Success Criteria

- users understand the output before exporting
- template differences are instantly visible
- the export center feels like a premium product feature, not a settings popup
